# M0.3 — Security certification gates

Status: **IN PROGRESS**. This branch must not be deployed or merged until the CI gates are green.

## M0.3.1 — Restricted runtime database role
- Provision a dedicated `hrm_runtime` login with no superuser, schema ownership, role-creation or BYPASSRLS privileges.
- Keep schema migration privileges with a separate Flyway principal.
- In production, configure `DB_USERNAME`/`DB_PASSWORD` for the runtime account and `SPRING_FLYWAY_USER`/`SPRING_FLYWAY_PASSWORD` for the migration account.
- The supplied SQL assumes the default local database name `hrm_dev`; adjust the database name and grant list for each deployment and subsequent migrations.
- Protect PostgreSQL credentials via secret management. Never put actual passwords on command line in production (process listing/history).
- The local Compose owner role is not a safe production runtime identity.
- The unrestricted `auth_identity` and `tenant` reads are only for trusted internal authentication and provisioning. Do not expose tenant data access directly via client-supplied IDs.

## M0.3.5 — RLS regression
Run `psql -v ON_ERROR_STOP=1 -f scripts/test-tenant-rls.sql` against an isolated disposable database after Flyway migrations. Requires a migration/admin connection. The test rolls back its data and test role.
