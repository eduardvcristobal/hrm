## Runtime configuration
Production must supply `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `INVITATION_FROM`, `INVITATION_ACCEPT_URL`, and `PASSWORD_RESET_URL`. Without mail configuration, issuance to valid users fails closed (503).
Use TLS-protected SMTP with managed credentials and an approved sender address. Never commit secrets.
Keep migration/owner and runtime DB accounts separate. The CI role script is intentionally aimed at a disposable `hrm_dev` database.

## M0.3.4.5 — Privileged TOTP MFA increment
- Flyway V7 stores a pending/active TOTP factor and replay counter; V8 stores API-token MFA assurance.
- Privileged users must confirm TOTP enrollment and supply a fresh TOTP during token issuance.
- Tenant administration routes require both TENANT_ADMIN and an MFA-assured Bearer token; Basic credentials alone cannot access them.
- CI verifies enrollment, replay rejection, denied token issuance before enrollment, elevated company operations, and token revocation.
- **Remaining critical caveats:** MFA secrets are currently stored as plaintext hexadecimal in the database. Encrypt factor secrets with managed keys before production. MFA recovery, device replacement, rate limits for code attempts, and broader step-up coverage are not yet accepted.
- A successful CI run does not establish full security certification.
